0. HOW TO USE THIS PLAN
================================================================================

  For each ticket:
    1. Read the industry 00-README-INDEX + named module doc
    2. Tag work: now | next | later | external
    3. Ship behind entitlements: has(moduleSku) + industry allows
    4. Update CHANGE LOG in the source doc when behaviour diverges

  Definition of “industry MVP shipped”:
    • Tenant can pick industry type on onboarding
    • Website plan works (Layer 1) for that industry
    • At least one core paid or free module path works end-to-end
    • Editor nav hides disallowed commerce
    • Superadmin can enable/disable industry + module SKUs + prices
    • Public site does not expose blocked flows (e.g. Presence cart)

================================================================================
1. HARD RULES (ALL PHASES)
================================================================================

  PLATFORM
    • Platform Postgres (Drizzle + DATABASE_URL) for config, billing, entitlements
    • Tenant operational data: Sheets default; BYO Supabase optional later
    • No secrets in git; Vercel/env for production

  PRODUCT
    • Website-first: Layer 1 site sells before complex ops modules
    • Modules priced separately (Select modules); bundles optional only
    • Google Calendar = FREE where events apply (tenant Gmail OAuth Connect)
    • Education video embeds = YouTube only
    • Presence = NO sales on ALINKS; Creator Partner = discount ↔ promote
    • Finance multi-brand insurance/loans = CALLED OFF (do not build)
    • Pharmacy = Phase 2 thin / gated later (other_verticals)
    • Retail: no multi-outlet POS seats product
    • RE: no property title checkout / escrow as default
    • Cloud kitchen: never dine-in / table QR

  BILLING SPLIT
    Platform Billing = tenant → Artix (website + modules)
    Tenant Checkout  = customer → shop (BYO Razorpay etc.) when commerce on

2. SHARED FOUNDATION (BUILD FIRST — BLOCKS ALL INDUSTRIES)
================================================================================
Phase code: F0
Priority: NOW

  F0.1 Industry registry
    IndustryGroup enum + types (from each pack’s superadmin catalog)
    Map legacy BusinessVertical → new groups where needed
    Flags per industry: commerce_modules_allowed, booking_modules_allowed,
                        sales_enabled, license_gates (clinic/pharmacy)

  F0.2 Module catalog + entitlements
    Table/config: module SKU, name, industry_allowlist[], monthly/yearly price,
                  charm99 yearly helper, optional bundle SKUs
    Tenant entitlements: has(sku), enable/disable one without cancelling others
    Caps: products, packages, staff, gallery, links, listings (plan or module)

  F0.3 Onboarding + registration upsell
    Pick industry → type → website plan → Select modules (allowed only)
    Soft upsell copy per industry docs (food 14, bookings 16, salon 16, …)
    Presence: Creator Partner terms checkbox when deep discount

  F0.4 Superadmin industry catalog
    CRUD prices, enable industry, coupons, creator discount fields
    Partner compliance fields (presence 06, 08)

  F0.5 Website plan Layer 1 (shared)
    Branding, theme, pages (≤5), SEO/OG, publish gate, WhatsApp/call CTAs
    Industry templates (starter pages/blocks) without full ops

  F0.6 Public site + editor gating
    editorLinksForVertical / industry-aware nav
    API guards: create-order blocked if !commerce; bookings blocked if !booking

  F0.7 Google tenant Connect (free Calendar)
    OAuth app platform-side; tenant Connect UX (integration_setup_docs/26)
    Free for applicable industries; no paid module SKU

  F0.8 Shared engines (stubs → full)
    Catalog engine     → retail, food menu, salon retail add-on, auto parts
    Appointments engine → salon, bookings, fitness, education slots, auto service
    Leads/forms engine  → RE, presence collab, auto enquiry, education enquiry
    Orders/checkout     → retail, food (tenant PG); never Presence
    Kitchen/tickets     → food only (later)

  Exit F0: one “general/presence” tenant + website plan live; module SKUs
           exist in Superadmin even if most industries still locked off.

WAVE 1 — ACQUISITION + CORE ENGINES          Priority: NOW
--------------------------------------------------------------------------------
  Goal: Paying website tenants + creator growth + first service vertical.

  W1.A  PRESENCE  (industries-docs/presence/)
    Why first: no commerce risk; Creator Partner acquisition; simple entitlements
    MVP:
      pr.presence_core, pr.link_stack, pr.gallery, pr.contact, pr.share_kit
      Hide Store/Checkout/Packages completely
      Creator Partner terms + discount ladder (docs 07–08) — even if promo
        compliance is manual Superadmin at first
    Next:
      pr.media_kit, pr.social_proof, pr.highlights, pr.analytics_lite
      Partner promo checklist + self-report URL
    Later:
      Referral codes, automated compliance scoring
    Docs: 01–08, ops 33
    DoD: influencer can publish link hub + collab form; commerce APIs 403

  W1.B  APPOINTMENTS CORE (shared) + SALON_BEAUTY MVP
    Why: reuses engine for bookings/fitness/edu; high India demand
    Shared:
      book.appointments_core — slots, resources, calendar UI, free client book
      Google Calendar free sync when connected
    Salon MVP (salon_beauty/):
      Packages list, free booking, staff roster light, website Layer 1
    Next:
      pay_then_book + tenant PG checkout, reminders/no-show
    Later:
      retail add-on products, multi-location salons
    Docs: salon 01–10, 14–16; bookings 04, 19; ops 29
    DoD: customer books free slot; tenant sees appointment in dashboard

  W1.C  FOOD — Layer 1 + light channels
    Why: huge market; start website + WA, not full kitchen day one
    MVP:
      Website + menu display + WhatsApp order CTA
      Types: cloud / restaurant / catering compatibility flags (no dine-in on cloud)
    Next:
      food.pickup, food.delivery (order list + status; riders later)
      food.catering enquiry
    Later:
      food.dine_in, food.kitchen, multi-branch, coupons, rider modes
    Docs: food 01–05, 07, 09–14; ops 24
    DoD: restaurant publishes menu; WA deep-link works; cloud cannot enable dine-in

  W1.D  RETAIL — storefront MVP
    Why: catalog engine shared with food modifiers later
    MVP:
      Multi-brand optional tags, categories, product list, storefront page
      Trade mode: retail only first
      Checkout: WA order or simple COD path if Pro commerce already exists
    Next:
      Tenant PG checkout, stock flags, variations
    Later:
      wholesale B2B (MOQ), marketplace multi-brand advanced
    Explicit NOT: multi-outlet POS, multi-vendor split settlement
    Docs: retail 01–05, 08–09, 13–15; ops 28
    DoD: shop lists products; customer can enquire/order without POS
