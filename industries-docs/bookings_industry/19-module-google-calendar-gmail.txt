SETUP MODEL (LOCKED)

  button — they never create API keys or a Google Cloud project.
  See 26-google-tenant-integrations-guide.txt for full steps + in-product copy.

================================================================================
1. DEFINITION
================================================================================

  Tenants connect THEIR Google account (Gmail / Google Workspace) so ALINKS
  scheduled events sync with THEIR Google Calendar — at no extra charge.

  • Calendar is tenant-owned — events live in their Google account.
  • ALINKS is system of record; Google Calendar is the day-view convenience.
  • Not Artix’s calendar; not a shared Artix Gmail.
  • FREE for everyone — not sold as an add-on module.

  Works for: clinics, lawyers, consultants, venue/banquet halls, salons,
  catering (event dates), and any other industry with bookable/scheduled work.

================================================================================
2. WHY IT MATTERS
================================================================================

  • Doctors/lawyers already live in Google Calendar.
  • Avoid double-booking personal meetings vs ALINKS appointments.
  • Banquet managers see holds alongside other events.
  • Instant trust: “it shows up in my Gmail calendar.”

================================================================================
3. WHO GETS IT (FREE — ALL APPLICABLE INDUSTRIES)
================================================================================

  BOOKINGS INDUSTRY

  uses one shared calendar per branch (config choice).

================================================================================
4. SYNC MODES
================================================================================

  A. PUSH (ALINKS → Google) — MVP required
     On booking confirm → create/update Google Calendar event
     On cancel/reschedule → update/delete event
     Event title/body from service + client first name (privacy-aware)

  B. PULL / BUSY BLOCKS (Google → ALINKS) — strongly recommended v1.1
     Read free/busy or events → block ALINKS slots when Google shows busy
     Prevents double-booking personal appointments

  C. TWO-WAY full edit from Google — later (conflict resolution hard)

  Default product: PUSH + free/busy PULL.

================================================================================
5. OAUTH & SCOPES (TENANT CONNECT)
================================================================================

  Distinct from platform service-account Sheets writes where used.
  Tenant “Connect Google Calendar” OAuth (user consent):

  Minimum scopes (refine at implement):
    • openid email profile (identity)
    • https://www.googleapis.com/auth/calendar.events
      (create/update/delete events on calendars user can write)
    • https://www.googleapis.com/auth/calendar.readonly
      OR calendar.freebusy for busy checks
    Avoid full calendar ownership unless needed.

  Optional later: Drive.file only if attaching files — not required for calendar.

  Token storage:
    • Refresh token encrypted at rest (platform secret box / PAYMENTS-style
      encryption pattern)
    • Per business_id and/or per resource_id (doctor’s own Gmail)
    • Never log tokens; never commit to git

  Disconnect:
    • Revoke token, stop sync, keep ALINKS bookings

  Google Cloud project:
    • Enable Google Calendar API
    • OAuth consent screen: ALINKS
    • Redirect: https://alinks.online/api/integrations/google-calendar/callback
      (+ localhost for dev)
    • May share GCP project with Sheets OAuth or separate client — document in
      integration_setup_docs when implementing

================================================================================
6. EVENT MAPPING (ALINKS BOOKING → GOOGLE EVENT)
================================================================================

  Google Event {
    summary:     "{Service name} — {Client first name or 'Client'}"
    description: ALINKS ref id, service, channel, notes (no full medical record)
    start/end:   booking start_at / end_at (timezone = business/branch TZ)
    location:    branch address or "Online" / meet link field
    attendees:   optional client email if provided + tenant opted in
    extendedProperties.private.alinks_booking_id
  }

  Clinic: do NOT put diagnosis or sensitive clinical data in description.
  Lawyer: do NOT put case strategy; consult type only.
  Venue:  hall name + package + guest count OK.

  Privacy default: minimal client PII on Google event (phone optional flag).

================================================================================
7. LIFECYCLE (100%)
================================================================================

  1. Discover     “Sync to your Google Calendar (Gmail) — free”
  2. Purchase     NONE — included free; no Billing line item
  3. Connect      OAuth with tenant Gmail / Workspace
  4. Configure    Choose calendar (primary or named “ALINKS”),
                  timezone, privacy flags, per-resource vs business calendar
  5. Operate      Auto push on confirm/cancel/reschedule; pull busy for slots
  6. Integrate    Instant with bookings + catering events + any scheduled type
  7. Health       Token refresh; on revoke show “Reconnect Google”
  8. Disconnect   Stop sync; optional delete future ALINKS-created events only
  9. “Disable”    Tenant turns off sync in settings only — not a paid cancel

================================================================================
8. SEAMLESS INTEGRATION WITH OTHER BOOKING MODULES
================================================================================

  book.core
    Every confirmed booking → calendar event; cancelled → remove/cancel event

  book.clinic
    Resource = doctor; prefer doctor’s connected calendar if multi-doctor
    License gate unchanged; calendar is operational only

  book.professional / book.legal
    Same push/pull; legal disclaimer not pasted into Google description by default

  book.venue
    Date package → multi-hour or all-day event on venue calendar
    Capacity still enforced in ALINKS, not in Google

  book.payments
    Free bookings (default): push on confirm immediately (no payment step)
    Paid modes: push only after pay-to-confirm succeeds (status=confirmed)
    Pending payment → no event OR “tentative” event (product flag)

  book.reminders
    Independent of Google’s own reminders; both may fire (tenant can disable one)

  book.multilocation
    Calendar selection per branch OR single brand calendar with location field

  food.catering (and cloud + catering)
    Confirmed catering event / production day → Google Calendar event
    Lead-only (not confirmed) → no push unless tenant enables “tentative leads”
    FREE — same capability, no catering-specific calendar fee

  food.delivery / restaurant ops (optional later)
    Optional shift or “delivery window” calendars — still free if offered

  food.dine_in
    Not a Google Calendar product focus (table QR meals); staff shifts optional

  Instant rule:
    Connecting Google Calendar does not create bookings by itself.
    Any confirmed Booking or Catering event automatically syncs if connected.
    Available free wherever ALINKS has a scheduled event type.

================================================================================
9. FAILURE & EDGE CASES
================================================================================

  • Token expired → queue reconnect; do not fail customer booking confirm
    (booking stays in ALINKS; sync retries)
  • Google API quota → exponential backoff queue
  • Conflict on free/busy → slot marked unavailable in ALINKS book UI
  • Manual edit in Google → v1 do not overwrite ALINKS source of truth
    (document: ALINKS is system of record for client bookings)
  • Two resources same Google account → use separate calendars or event titles

13. SECURITY & COMPLIANCE
================================================================================

  • Encrypt tokens; least scopes; disconnect path
  • DPDP: client data on Google is tenant’s Google account — tenant is
    responsible for their Google Workspace policies
  • ALINKS ToS: sync is optional convenience; ALINKS remains booking record
  • No storing Google password — OAuth only
